# InventorySnapshot

![Java 21](https://img.shields.io/badge/Java-21-orange)
![Paper 1.21](https://img.shields.io/badge/Paper-1.21.1%2B-blue)
![Build: Maven](https://img.shields.io/badge/build-Maven-red)

A [Paper](https://papermc.io/) plugin that saves **snapshots of player inventories** to an embedded database and lets you list and restore them. Every item is captured with its full metadata (enchantments, names, lore, custom data) and stored as a Base64 string in an **H2** database.

Useful for recovering items after deaths, bugs, or griefing, and as a safety net before risky changes.

---

## Features

- Full inventory capture: storage, hotbar, armor, and offhand, with slot positions preserved
- Ender chest capture
- Complete item metadata through Paper's native item byte serialization (survives Minecraft data upgrades)
- Embedded **H2** database, so no external database server is needed
- **HikariCP** connection pool with fully asynchronous database access (no main-thread lag)
- Automatic snapshots on player death and quit
- In-game commands to save, list, and restore snapshots
- Safety snapshot taken automatically before every restore

## Requirements

| Requirement | Version |
|---|---|
| Server software | [Paper](https://papermc.io/) 1.21.1 or newer |
| Java | 21 or newer |

> The plugin uses Paper-specific APIs (item byte serialization), so Spigot and other Bukkit forks are not supported.

H2 and HikariCP are **bundled inside the plugin jar**, so the server needs no extra libraries and no internet access.

## Installation

1. Download the latest jar from the [Releases](https://github.com/ilattesoft/InventorySnapshot/releases) page, or [build it yourself](#building).
2. Put the jar in your server's `plugins/` folder.
3. Start the server and check the console for the `Database ready` message.
4. Grant the permission below to whoever should use the plugin.

The database is created inside `plugins/InventorySnapshot/`.

## Commands

| Command | Description |
|---|---|
| `/snapshot save` | Save a snapshot of your current inventory |
| `/snapshot list` | Show your 10 most recent snapshots |
| `/snapshot restore <id>` | Restore a snapshot by id (a `PRE_RESTORE` snapshot is taken first) |

## Permissions

| Permission | Description | Default |
|---|---|---|
| `inventorysnapshot.use` | Use the `/snapshot` command | op |

## Automatic snapshots

| Trigger | Reason tag |
|---|---|
| Player dies (captured before drops are cleared) | `DEATH` |
| Player disconnects | `QUIT` |
| `/snapshot save` | `MANUAL` |
| Before a restore | `PRE_RESTORE` |

## How it works

1. **Capture (main thread):** inventory contents are read, serialized to bytes, and Base64-encoded. Bukkit inventory access is not thread-safe, so this always runs on the main thread.
2. **Save (database threads):** the Base64 strings are inserted into H2 through a HikariCP-pooled connection on a dedicated executor.
3. **Restore:** the snapshot is loaded asynchronously, then applied to the player back on the main thread.

## Database

Snapshots are stored in a single table:

```sql
CREATE TABLE inventory_snapshots (
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    player_uuid  VARCHAR(36)  NOT NULL,
    player_name  VARCHAR(16)  NOT NULL,
    created_at   BIGINT       NOT NULL,   -- epoch millis
    reason       VARCHAR(32)  NOT NULL DEFAULT 'MANUAL',
    world        VARCHAR(64),
    x            DOUBLE PRECISION,
    y            DOUBLE PRECISION,
    z            DOUBLE PRECISION,
    inventory    CLOB         NOT NULL,   -- Base64
    ender_chest  CLOB,                    -- Base64
    total_xp     INT,
    health       DOUBLE PRECISION,
    food_level   INT,
    data_version INT          NOT NULL    -- Minecraft data version at save time
);
```

### Database files

H2 appends its own suffixes to the base name in the JDBC URL:

| File | Purpose |
|---|---|
| `<name>.mv.db` | The actual data file |
| `<name>.trace.db` | Error log. Only appears if H2 hit an error, so read it if it shows up |

Good to know:

- Only **one process** can open the database file at a time, so two servers cannot share it.
- To back up, stop the server and copy the `.mv.db` file.
- H2 1.4.x and 2.x files are not compatible. Stay on the 2.x series when upgrading.

## Building

**Requirements:** JDK 21+ and [Maven](https://maven.apache.org/).

```bash
git clone https://github.com/ilattesoft/InventorySnapshot.git
cd InventorySnapshot
mvn clean package
```

The finished plugin jar is written to `target/`:

```
target/inventorysnapshot-1.0-SNAPSHOT.jar
```

(The default Maven goal is already `clean package`, so running plain `mvn` works too. Ignore the `original-*.jar` file, which is the unshaded version without the bundled libraries.)

### Dependencies

| Dependency | Version | Scope |
|---|---|---|
| Paper API | 1.21.1-R0.1-SNAPSHOT | provided (supplied by the server) |
| H2 | 2.5.252 | bundled with `maven-shade-plugin` |
| HikariCP | 7.1.0 | bundled with `maven-shade-plugin` |

### plugin.yml

Resource filtering is enabled in the `pom.xml`, so `plugin.yml` in `src/main/resources` can reuse the Maven version:

```yaml
name: InventorySnapshot
main: me.iLatteSoft.inventorySnapshot.InventorySnapshot
version: ${project.version}
api-version: '1.21'

commands:
  snapshot:
    description: Save, list or restore inventory snapshots
    usage: /snapshot <save|list|restore>
    permission: inventorysnapshot.use

permissions:
  inventorysnapshot.use:
    default: op
```

## Development notes

- **Threading:** touch Bukkit objects (inventories, worlds, entities) on the main thread only. Database callbacks run on a database thread, so use `Bukkit.getScheduler().runTask(plugin, ...)` before applying anything to a player.
- **Shutdown:** `DatabaseManager.close()` waits for queued writes to finish before closing the pool, so quit and shutdown snapshots are not lost.
- **Data version:** each snapshot records the Minecraft data version it was created under, which helps when diagnosing restores after a server upgrade.
- **Shading:** H2 and HikariCP are bundled without relocation. If another plugin on your server bundles a different version of either library, consider adding a relocation rule for it in the `maven-shade-plugin` configuration.
- **Switching databases:** only the `HikariConfig` block and the schema syntax in `DatabaseManager` are database-specific, so moving to MySQL or MariaDB later is straightforward.

## Troubleshooting

| Problem | Likely cause |
|---|---|
| Plugin fails to enable with a database error | Check the console stack trace and the `.trace.db` file next to the database |
| Old snapshots "disappeared" after a code change | The JDBC URL base name changed, so H2 created a new empty database. Rename the old `.mv.db` file to match |
| Plugin refuses to load on an older server | Paper 1.21.1+ and Java 21 are required |
| Items restored into the wrong slots | Make sure the full `getContents()` array is used when restoring, not storage-only |
